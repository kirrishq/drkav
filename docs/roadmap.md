- [x] Настроить pnpm-монорепозиторий.
- [x] Добавить Next.js-приложение и контракты контента.
- [x] Зафиксировать технические и эксплуатационные границы.

## 1. Исследование и информационная архитектура

- [x] Инвентаризировать существующие URL, шаблоны и SEO-метаданные для operation pages.

- [ ] Определить стратегию сохранения URL и 301-редиректов.

## 2. Дизайн-система и интерфейс

- [x] Создать минимальные shared design tokens и внутреннюю страницу документации.
- [x] Реализовать доступный `Button` как первый контролируемый компонент.
- [x] Реализовать `Input`, `Label` и базовую композицию `FormField`.
- [x] Добавить `PhoneInput` с маской, `Checkbox`, `Radio` и `RadioButton`.
- [ ] Утвердить визуальное направление.
- [ ] Добавлять следующие компоненты по одному в отдельных задачах.
- [ ] Вернуться к Storybook после стабилизации финальных компонентов.
- [ ] Реализовать основные страницы на статическом контрактном контенте.

## 3. Контент и запуск

- [x] Выбрать Strapi 5.51.1 для локальной разработки и добавить `apps/cms` с локальной SQLite.
- [x] Подготовить CMS-neutral модели, `ContentRepository` и изолированный Strapi-адаптер.
- [x] Подключить операцию «Увеличение груди» как первую безопасную вертикаль и проверить отсутствие draft/runtime fallback.
- [x] Добавить production cache, build-time pre-generation, last-known-good и route error boundary для первой CMS-вертикали.
- [x] Добавить совместимый branded HTTP 500 для ранней static/ISR ошибки, которую Next.js 15.5.22 не передаёт App Router segment boundary.
- [ ] До production выбрать hosting/cache handler и внешний media provider; проверить tag revalidation на выбранной платформе.
- [ ] После выбора hosting реализовать защищённый Publish webhook и внешний monitoring отдельными задачами.
- [x] Перенести 36 подтверждённых operation pages в Strapi; оставить одну неполную страницу draft до утверждения контента.
- [ ] Провести медицинскую и редакторскую проверку предупреждений из `operation-cms-migration-report.md`.
- [ ] Проверить контент, доступность, производительность и SEO.
- [ ] Отдельно согласовать Public API, production, hosting, DNS, amoCRM, аналитику, другие реальные интеграции и публикацию.
